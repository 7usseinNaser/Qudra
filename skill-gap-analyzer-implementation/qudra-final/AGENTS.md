# AGENTS.md — نقطة الدخول الإلزامية لوكلاء QUDRA

> هذا الملف **ليس** مصدر الحقيقة — إنه **خريطة توجيه سريعة** تدلّك أين تجد كل شيء قبل أن تبدأ العمل. اقرأه أولاً في أي جلسة عمل جديدة، ثم اذهب فوراً للملفات التي يُشير إليها.

> **لا تفترض. لا تخترع. افحص الموجود أولاً. استخدم Find-Skills قبل التنفيذ. استخدم Grill-Me عند الغموض. نفّذ بأبسط بنية قابلة للتوسع، ثم اختبر كالمستخدم، وتحقق كأدمن، ووثّق كل شيء قبل إعلان الإنجاز.**

## القاعدة الأهم فوق كل القواعد

**لا تفترض. لا تخترع. إذا لم يكن الشيء موثّقاً بوضوح في أحد ملفات هذا المشروع → توقف واسأل حسين مباشرة.**

طبّق أسلوب "Grill Me" (موثّق في `SKILLS.md`) عند أي غموض: أسئلة استقصائية متتالية عميقة، وليس سؤالاً سطحياً واحداً.

---

## ملخص فكرة المشروع في 3 أسطر

قُدرة (QUDRA) منصة عربية RTL لمطابقة المشكلات بالأشخاص بناءً على **أدلة حقيقية مُثبتة** (Proven) وليس ادعاءات ذاتية (Claimed). النموذج: `Problem → Capability → Evidence → Match → Outcome → New Evidence`. المرحلة الحالية (B0): إعادة بناء `prototype.html` كتطبيق React/TypeScript كامل، بمعمارية نظيفة قابلة للتوسع، دون تغيير أي بكسل من التصميم الحالي.

---

## قبل كل Task

- افهم المطلوب بدقة (Grill-Me إذا فيه غموض).
- افحص الموجود فعلياً (`PROJECT_MAP.md` + الكود الحالي) — لا تعِد بناء ما هو موجود بلا سبب.
- نفّذ Find-Skills وفعّل المهارات المناسبة.
- خطّط قبل الكود.

## بعد كل Task

- اختبر (typecheck, lint, build).
- اختبر كالمستخدم فعلياً.
- اختبر كـ Admin/Test User عندما تكون الأدوات والبيئة متاحة — جرّب كل زر وتفاعل جديد فعلياً.
- راجع Responsive / RTL / Dark Mode / Accessibility.
- حدّث ملفات التتبع: `TASKS.md`, `STATUS.md`, `CHANGELOG.md`, وعند الحاجة `DECISIONS.md`.
- حدّث `PROJECT_MAP.md` لكل ملف جديد أو مُعدَّل جوهرياً (راجع صيغة الإدخال في `PROJECT_MAP.md` نفسه).
- أنشئ سجل تفصيلي في `.memory/tasks/YYYY-MM-DD_<TASK-ID>.md`.
- **لا تدّعِ `100% verified` أو `production ready` أو `fully tested` بدون دليل فعلي موثّق في `TEST_REPORT.md`.**
