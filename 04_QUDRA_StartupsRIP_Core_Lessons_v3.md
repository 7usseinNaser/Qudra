# قُدرة — Startups.RIP: Core-Compatible Lessons v3

## الهدف

نأخذ من Startups.RIP المبادئ التي تقوي Core قُدرة، لا المنتجات كاملة.

## 1. Triplebyte

الدرس: demonstrated skill أقوى من الاعتماد الكامل على
credentials/resume. أخذنا منه: structured assessment، practical
evidence، matching. قُدرة تضيف فوق ذلك Existing Evidence + Challenges +
Outcome Evidence.

## 2. Bits to Atoms

الدرس: Matching للمتطلبات المتخصصة يحتاج Skill Gap handling. نضيف:
Match + Gap + Practice + Proof، بدل الرفض فقط.

## 3. Gigster

الدرس: تحويل وصف المشروع إلى خطة وقدرات وفريق. نأخذ مستقبلًا: Problem →
Required Capabilities → Team، ولا ندخل managed service أو quote في MVP.

## 4. Codecademy

الدرس: ربط التعلم بالأداء العملي كان اتجاهًا مبكرًا. في قُدرة يصبح: Learn →
Practice → Prove → Match.

## 5. Feature — Evidence Passport

رابط قابل للمشاركة يحتوي Skills + Evidence + Verification + Readiness
بدل CV فقط.

## 6. Feature — Evidence Timeline

تطور القدرة زمنيًا: مشروع → Challenge → Company Challenge → Assessment.

## 7. Feature — Evidence Freshness

الدليل الحديث له وزن أكبر من الدليل القديم، حسب نوع المهارة.

## 8. Feature — Evidence Diversity

تنوع الأدلة أقوى من تكرار نفس النوع: Project + Challenge + External
Verification + Outcome + Interview.

## 9. Feature — Evidence Confidence

High / Medium / Low بناءً على المصدر والعدد والتنوع والحداثة والصلة
والتحقق.

## 10. Feature — Challenge Ladder

Beginner → Intermediate → Advanced → Expert، لكن المستوى لا يفتح بمجرد
كتابة الاسم؛ يجب وجود Evidence مناسب.

## 11. Feature — Company Challenge

الشركة تنشر مشكلة حقيقية؛ المستخدم يحلها؛ النتيجة تصبح Company Evidence.
هذه من أقوى إضافات الرؤية طويلة الأمد.

## 12. Feature — Re-match After Evidence

قبل التحدي 78%، بعد Evidence جديدة 91%. هذه تجربة Demo قوية لأنها توضح
أن الدليل يغير القرار.

## 13. Feature — Capability Graph

بدل قائمة Skills، العلاقات بين Frontend/React/TypeScript/Testing وغيرها،
مع Evidence مرتبطة بكل عقدة.

## 14. Feature — Problem → Capability Graph

المشكلة نفسها تتحول إلى Graph، ثم تُقارن بـCapability/Evidence Graph
للمستخدمين.

## 15. Feature — Evidence Quality Gate

فحص الرابط، وجود المشروع، الصلة بالمهارة، الحداثة، التضارب، وإشارات
الأصالة. هدفه مكافحة Evidence الوهمي.

## 16. Feature — AI Interview Coach

مقابلة صوتية قبل مقابلة الشركة، مبنية على User Intelligence Profile
وSkill Gaps، ثم Practice → Improve → Re-test.

## 17. Feature — Opportunity Readiness

بدل Match فقط: Ready Now / Nearly Ready / Needs Evidence.

## 18. Feature — Human + AI Allocation

بعد تحليل المشكلة: ما الذي ينفذه الإنسان؟ ما الذي ينفذه AI؟ ما الذي
يحتاج مراجعة بشرية؟ مستقبلًا تصبح جزءًا من Team/Solution Composer.

## 19. Feature — Evidence-Based Team Composer

الفريق يبنى بناءً على Capability Coverage، لا Titles.

## 20. Feature — Outcome Evidence

بعد المشروع، تُسجل مساهمة كل عضو والنتيجة ثم تتحول إلى Evidence جديدة.

## 21. ترتيب الإضافات

### P0

Evidence Profile، Evidence Analysis، Explainable Match، Skill Gap. \###
P1 GitHub Deep Analysis، External Evidence، Re-match، Evidence Graph،
Quality Gate. \### P2 Company Challenges، Oral Evidence، Personalized
Roadmap، Evidence Passport، Opportunity Readiness. \### P3 Team
Composer، Human + AI Composer، Workspace، Outcome → Evidence. \### P4
Project Intelligence، Market Research، Competitor Analysis، Risk
Analysis، Revenue Signals، Marketplace.

## القرار

أفضل ما أخذناه من Startups.RIP هو تقوية المبدأ: **Demonstrated Skill \>
Claimed Skill**، ثم تحويل Gap إلى مسار: **Skill Gap → Practice → Proof →
Match**، ثم بناء Company Problem → Challenge → Evidence → Talent
Discovery.
